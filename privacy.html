AgentLedger (Atlassian Forge app)

  • What is stored. AgentLedger stores, per Jira issue key, an append-only attestation trail: the action taken, the agent reference, the agent id, the verdict, a reason, a timestamp and a hash that commits to the previous entry. It also stores the site's cloud id so it can query Atlassian's Teamwork Graph.
  • What is not stored. No account credentials, no issue content, no comments, no attachments and no personal data of the people who comment on an issue.
  • Who can read it. Only the users of the Atlassian site where the app is installed, and only through that site's own permissions. The trail is visible in the issue panel to anyone who can view the issue.
  • Where it runs. On Atlassian's own infrastructure. AgentLedger is a Forge app: the code runs in Atlassian's sandboxed runtime and the data is held in Atlassian's key-value store for the app. There is no separate server operated by Leonard Sambu and no copy of your data leaves Atlassian.
  • External calls. The app calls a registry you give it a reference for, by default the Concordium Agent Registry, to check that an agent identity is valid. The lookup sends the agent reference (a public on-chain token address or agent id). It also reads a public agent card the registry points at. Nothing about your Jira issue is sent to that registry.
  • Deletion. A site administrator can uninstall the app, which removes its key-value store entries. Uninstalling is the fastest way to delete the trail.
